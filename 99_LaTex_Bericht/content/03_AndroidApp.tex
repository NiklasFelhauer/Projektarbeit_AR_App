\section{Android App}

\subsection{MainViewModel}
In diesem Projekt spielt das Datenmanagemet eine wichtige Rolle, da sich Werte kontinuierlich ändern und gleichzeit global in der App verfügbar sein müssen. Dieser Datenfluss wird im \verb|MainViewModel| der App gesteuert. Es handelt sich um eine default Android-Komponente, die Daten im Hintergrund unabhängig von der UI (User Interface) verwaltet. 
Das ist notwendig, weil Tabs oft komplett neu geladen werden, nachdem zwischen den Tabs gewechselt wird.

\subsubsection{Kamera-Tab}
Der Kamera-Tab wird standardgemäß als erstes beim Starten der App geöffnet und nutzt die CameraX-API, um den Kamera-Livestream des Smartphones anzuzeigen. Jedes Frame (einzelnes Bild) wird an die \verb|ObjectDetectorHelper|-Klasse geschickt, welche das benutzerdefinierte Tensorflow-Lite Modell \verb|Tanks_V2.tflite| nutzt, um Tanks der Brauanlage zu erkennen und die Koordinaten der zugehörigen Bounding-Boxen zu berechnen.
In der \verb|OverlayView|-Klasse wird der Tank-Name, Erkennungssicherheit des Modells (Score) und die aktuelle Temperatur als Overlay auf einem erkannten Tank angezeigt. Die Temperaturdaten kommen regelmäßig per MQTT direkt von den Temperatur-Sensoren der Brauanlage im JSON-Format, zum Beispiel als:
\lstinline|{"tank_1": 65.5, "tank_2":70.2, "tank_3": 23.4, ...}|
Diese Daten werden im MainViewModel verarbeitet.

In der \verb|CameraFragment|-Klasse werden die Temperatur-Daten aus dem MainViewModel kontinuierlich beobachtet.
